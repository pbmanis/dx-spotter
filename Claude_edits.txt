ARCHITECTURE NOTES
─────────────────────────────────────────────────────────────────────────────

Thread model:
  Main thread    — Qt event loop, all UI updates, QTimer callbacks
  MQTT thread    — paho loop_start() background thread; calls on_message()
                   which emits window.new_spot (queued cross-thread signal)
  WSJT-X thread  — WsjtxListener._run() daemon thread; calls _on_wsjt_spot()
                   which emits window.new_spot (queued cross-thread signal)
  Counter safety — psk_counter / wsjt_counter are only incremented from their
                   respective threads and read (not written) from the main
                   thread timer; safe under CPython's GIL.

Spot display pipeline:
  on_message / _on_wsjt_spot
    → increment source counter
    → apply country / range / show filters
    → compute adif_status
    → window.new_spot.emit(spot_dict)   [cross-thread queued signal]
    → SpotTable.add_spot()              [main thread, appends to _pending_spots]
    → _flush_pending() every 250 ms    [main thread timer, batches table writes]

BUGS FOUND AND FIXED
─────────────────────────────────────────────────────────────────────────────

BUG 1 — Sending Reply (type 4) to the wrong port
─────────────────────────────────────────────────
Root cause: WSJT-X sends UDP packets FROM an ephemeral source port (e.g.
63326) TO the configured "UDP Server Port" (2237).  PSKSpotter was sending
all outgoing commands TO port 2237 — i.e. back to our own recv_sock, which
immediately swallowed them.  WSJT-X never saw any Reply at all.

Discovery: tcpdump hex capture of a working packet from RumLogNG decoded to
show source port 63326.  That ephemeral port is where WSJT-X's own receive
socket lives; commands must go there.

Fix (src/wsjtx_listener.py):
  __init__: added  self._wsjt_src_port: int = 0
  _run(): on first recvfrom(), capture addr[1] as _wsjt_src_port
  _send(): destination changed to (self._wsjt_host, self._wsjt_src_port)

BUG 2 — Port contention: no packets received (_wsjt_host remained None)
─────────────────────────────────────────────────────────────────────────────
Root cause: macOS uses BSD socket semantics.  With SO_REUSEADDR only,
unicast datagrams go to the most recently bound socket on a port.  When
RumLogNG or GridTracker2 bound port 2237 after PSKSpotter, PSKSpotter's
recv_sock received nothing.

Fix (src/wsjtx_listener.py _run()):
  recv_sock.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
  if hasattr(socket, 'SO_REUSEPORT'):
      recv_sock.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEPORT, 1)

  SO_REUSEPORT on BSD/macOS delivers a copy of each unicast datagram to
  every socket bound to the same port, enabling coexistence with all
  companion apps.  The hasattr() guard keeps it safe on non-macOS.

BUG 3 — Stale decode fields in Reply (time_ms, delta_t, msg)
─────────────────────────────────────────────────────────────
Root cause: The _RESHOW_SECS = 300 display gate suppressed re-emitting
spots to the table for 5 minutes.  The decode dict used for Reply was also
only written inside the display-gate check, so stored time_ms / delta_t /
msg could be 5 minutes old.  WSJT-X uses time_ms to locate the row in Band
Activity (which rolls over each ~15 s decode period), so stale values caused
lookup misses and Reply had no effect.

Fix (src/wsjtx_listener.py _handle() Decode branch):
  self._latest_decode: dict[str, dict] = {}  added in __init__
  In the Decode branch, BEFORE the display-gate early-return, store:
      self._latest_decode[dx_call] = {
          'ms': ms, 'snr': snr, 'delta_t': delta_t,
          'df': df, 'mode': mode, 'msg': msg,
      }
  New public method get_latest_decode(call) -> dict | None returns this.
  _on_spot_activated() (pskspotter.py) calls get_latest_decode() first;
  uses those exact fields if found, falls back to spot-row values otherwise.

BUG 4 — .strip() on message text could corrupt Reply match
────────────────────────────────────────────────────────────
Root cause: Earlier code had  msg = r.utf8().strip().  WSJT-X uses the
exact message string for band-activity lookup; stripping trailing spaces
could break the match.

Fix: msg = r.utf8()  — verbatim, no .strip()

BUG 5 — Previous highlight not cleared when a new call is clicked
─────────────────────────────────────────────────────────────────
Root cause: highlight_call() only sent the new type-13 highlight; it never
sent a clear for the previously highlighted call, so highlights accumulated.

Fix (src/wsjtx_listener.py highlight_call()):
  self._last_highlighted: str = ''  added in __init__
  Before sending the new highlight, if _last_highlighted differs, send a
  type-13 with invalid (clear) colors for the previous call, then update
  _last_highlighted = callsign before sending the new highlight.

BUG 6 — Qt QColor serialization format was wrong
──────────────────────────────────────────────────
User-supplied _pack_qcolor() had wrong field order (alpha after r/g/b) and
1-byte pad instead of 2.  Correct QDataStream schema >= 7 format:
  struct.pack('>bHHHHH', spec, alpha, r*257, g*257, b*257, pad)
  spec=1 RGB / spec=0 invalid(clear), alpha=0xFFFF, pad=0.

PROTOCOL NOTES (for future reference)
─────────────────────────────────────────────────────────────────────────────

WSJT-X UDP port model:
  WSJT-X sends FROM ephemeral port (e.g. 63326) TO configured port (2237).
  Commands to WSJT-X must go TO the ephemeral port, not 2237.

Reply (type 4) payload (big-endian):
  quint32  time_ms        ms since UTC midnight
  qint32   snr
  double   delta_t        seconds
  quint32  delta_freq_hz  audio offset
  QString  mode           e.g. "FT8"
  QString  message        exact decoded text e.g. "CQ N1ABC FM05kw"
  bool     low_confidence = False
  quint8   modifiers      = 0

Highlight Callsign (type 13) payload:
  QString  callsign
  QColor   bg_color       11 bytes
  QColor   fg_color       11 bytes
  bool     last_only      = False

QColor encoding (11 bytes, big-endian QDataStream schema >= 7):
  qint8   spec    1=RGB, 0=invalid/clear
  quint16 alpha   0xFFFF = opaque
  quint16 r       component * 257
  quint16 g       component * 257
  quint16 b       component * 257
  quint16 pad     0

NEW FILE: src/telnet_cluster.py
───────────────────────────────

Module provides  TelnetCluster(threading.Thread)  — a daemon thread that
connects to a DX cluster node via TCP, logs in with the operator's callsign,
and forwards parsed spot lines to a callback.

Two spot line formats recognized:

  Standard (AR-Cluster / DXSpider):
    DX de <spotter>:    <freq_kHz>  <dx_call>    <comment>
    e.g.  DX de K4HWS:     14040.0  VA7MM        CW      VE 0236Z

  Alternate (used by some nodes):
    <freq_kHz>  <dx_call>   <DD-Mon-YYYY>  <HHMMZ>   <comment>  <<spotter>>
    e.g.  14292.0  EA3KT       01-Jul-2026 0221Z      EA <N5VBP>

  _process_line() tries the standard regex first; falls back to the alternate
  regex.  Lines matching neither format are silently skipped.

SNR: extracted from comment if present (e.g. "-10 dB"); defaults to '0'.
Mode: keyword extracted from comment first (FT8, FT4, FT2, CW, SSB, …),
      then inferred from frequency using:
        _FT_FREQS — FT8/FT4/FT2 channel centres (±1 kHz tolerance)
        _CW_SEGMENTS — IARU Region 2 CW sub-band segments
        _SSB_SEGMENTS — IARU Region 2 SSB sub-band segments
      Unrecognized frequencies fall back to 'CW'.

Reconnection: exponential back-off (5 s → 10 → 20 → 40 → 60 s max).

stop() method: sets a threading.Event AND calls sock.shutdown(SHUT_RDWR) to
unblock a recv() immediately, so the thread exits without waiting for the
120-second socket timeout.  Socket reference cleared in _connect_and_run
with try/finally.

Keepalive: on socket.timeout (120 s) a bare '\r\n' is sent to detect stale
connections before the reconnect cycle.

Telnet IAC option negotiation bytes are stripped via _strip_iac() before
line splitting (some nodes send IAC negotiation on connect).

SpotCallback = Callable[[dict], None] — type alias for the on_spot parameter.
Spot dict keys: call, rc, rl, abs_freq_hz, rp, md, unix_time, comment.

Class  MqttListener  wraps a paho.mqtt.client.Client.

Constructor:
  host : str         — MQTT broker hostname
  port : int         — MQTT broker TCP port
  topic : str        — initial subscription topic

  .stop()                 — loop_stop() + disconnect()

                            safe to call with the same topic (forces resub)

  _handle_disconnect() — sets self._connected = False
  _handle_message()    — json.loads(msg.payload) → calls self._on_spot(payload)
                         on JSONDecodeError, prints and returns

SpotCallback = Callable[[dict], None]  (module-level type alias)

json and paho imports are fully contained in this module; dxspotter.py no

─────────────────────────────────────────────────────────────────────────────
TASK 1 — Diagnose "clusters not parsing"
─────────────────────────────────────────────────────────────────────────────

Method: wrote a throwaway probe that connected to the enabled clusters
(dxc.w3lpl.net:7373, telnet.reversebeacon.net:7000, K1RFI.com:7300 — all as
NC3G), captured every raw line AND the parse outcome, so parse failures could
be told apart from filter drops.

Finding: PARSING WORKS. w3lpl parsed 5/5 spot lines, RBN 179/183; the "unparsed"
counts were login banners, not spots. The pipeline was being starved by two
things downstream of the parser:

  ① cty.plist parse crash (root cause).  country-files.com renamed DXCC entity
     409 "Cape Verde" -> "Cabo Verde"; pyhamtools 0.12.0's
     countryfilemapping.json only knows "Cape Verde", so
     LookupLib(lookuptype="countryfile") raises KeyError: 'Cabo Verde' while
     parsing.  No try/except at the build site (dxspotter.py:1125) => the app
     CRASHES at startup once the 30-day cty cache expires and re-downloads.
     If it had degraded to cinfo=None instead, get_dxcc() returns -1 for every
     call, which silently breaks award coloring AND (when on) the us/ca filter.
     Checked all 345 country names in the current plist — "Cabo Verde" is the
     ONLY mismatch.

  ② telnet_us_ca_spotters_only = true (by design, but drops almost everything).
     _on_telnet_spot drops any spot whose SPOTTER isn't DXCC 291 (US) or 1
     (Canada). On RBN / world clusters the spotters are global, so nearly all
     spots vanish. Combined with ①, 100% of telnet spots dropped.
